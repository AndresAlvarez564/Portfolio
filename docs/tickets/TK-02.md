## Objective
Map every user flow and business process before any code is written. This ensures the data model and backend logic are designed around real usage patterns.

## Proposed Scope
- Document every flow a user can perform in the system.
- Include happy paths and error paths.
- Identify which flows require authorization checks.

- [ ] Identify which flows affect the data model

- The data model ticket (TK-03) can be written based on these flows.
- No feature ticket is created for a flow that is not documented here.
