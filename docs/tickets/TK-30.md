## Objective
Implement the contact Lambda routes, the public Contact page with form submission, and the admin Contact Messages management page. The contact form sends a message to SQS for async email notification (implemented in TK-32).

## Proposed Scope
- Backend: `POST /contact` (public, spam-protected), `GET /contact`, `GET /contact/:id`, `PATCH /contact/:id` (admin only)
- Frontend public: Contact page with validated form
- Frontend admin: Contact Messages page with list, view, and status management
- Observability: CloudWatch alarms and structured logs for the contact Lambda

## Flow

```
Public: POST /contact
↓
Lambda validates honeypot field (must be empty)
↓
Lambda validates required fields and message length
↓
Lambda saves CONTACT_MESSAGE to DynamoDB (status: unread)
↓
Lambda sends message to SQS queue (async email notification)
↓
Lambda returns 200 OK immediately (does not wait for email)

Admin: GET /contact
↓
Lambda validates admin group
↓
Query GSI-1 gsi1pk=CONTACT sort by gsi1sk desc (most recent first)
↓
Optional filter: ?status=unread|read|archived

Admin: PATCH /contact/{id}
↓
Lambda validates admin group
↓
UpdateItem: status field + gsi1sk update
↓
Returns updated message
```

## Acceptance Criteria
- `POST /contact` saves the message and returns 200
- `POST /contact` returns 200 silently when honeypot is triggered (no error revealed)
- `POST /contact` returns 400 for missing required fields or invalid email
- `POST /contact` returns 400 if message exceeds 2000 characters
- `GET /contact` returns messages sorted by date descending (admin only)
- `GET /contact` supports `?status=` filter
- `PATCH /contact/{id}` updates status and `gsi1sk`
- All admin routes return 403 without admin group
- Public Contact page submits form and shows success confirmation
- Admin Messages page lists messages with status filter tabs
- Message detail modal shows full content and status actions
- All unit tests pass
- CloudWatch alarms exist for the contact Lambda

## Notes
- The honeypot field must be a hidden input in the form — bots fill it, humans don't
- Never return an error when the honeypot is triggered — silently return 200 to avoid revealing the spam detection
- SQS integration: the Lambda sends to the queue but does not wait for the email worker — the API response is immediate
- `CONTACT_QUEUE_URL` must be added to the contact Lambda environment variables in CDK
- The SQS queue and email worker are implemented in TK-32
