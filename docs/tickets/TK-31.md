## Objective
Implement the media Lambda routes for S3 pre-signed URL upload, upload confirmation, media listing, and deletion. Also implement the reusable `MediaUpload` frontend component used by the certifications and profile modules.

## Proposed Scope
- Backend: `POST /media/upload` (generate pre-signed URL), `POST /media/confirm` (save metadata), `GET /media` (list), `DELETE /media/:id` (delete from S3 and DynamoDB) — all admin only
- Frontend: reusable `MediaUpload` component used in certification badge upload, project thumbnail/screenshots, and CV upload
- Observability: CloudWatch alarms and structured logs for the media Lambda

## Flow

```
Admin selects a file in the UI
↓
Frontend calls POST /media/upload with { filename, contentType, context }
↓
Lambda validates admin group
↓
Lambda generates pre-signed S3 URL (valid 5 minutes)
↓
Lambda returns { uploadUrl, s3Key }
↓
Frontend uploads file directly to S3 using the pre-signed URL (PUT request)
↓
Frontend calls POST /media/confirm with { s3Key, mediaType, context, relatedId }
↓
Lambda saves MEDIA record to DynamoDB
↓
Lambda returns { mediaId, cloudfrontUrl, s3Key }
↓
Frontend uses cloudfrontUrl to display the uploaded file
```

## Notes
- The pre-signed URL is a PUT request directly to S3 — the frontend must use `fetch` or `axios` with `method: PUT` and the correct `Content-Type` header
- `CLOUDFRONT_MEDIA_URL` is the CloudFront domain for the media bucket (without trailing slash)
- CV upload replaces the previous CV — `PROFILE_SETTINGS.cvFileUrl` is updated to the new file
- Old S3 objects are not deleted on CV replacement — they can be cleaned up via S3 lifecycle policy
- `MediaUpload` is a shared component — it will be used in TK-29 (certifications badge), TK-25 (project screenshots), and TK-24 (CV upload in profile settings)
